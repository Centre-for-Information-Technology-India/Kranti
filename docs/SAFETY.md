# Kranti Safety, Privacy and Moderation

Kranti may contain allegations, sensitive incidents, personal information and evidence. Safety is a product requirement.

## Distinguish
1. Citizen-submitted claim.
2. Submitted evidence.
3. Platform verification.
4. Official statement/response.
5. Resolution verification.

Never collapse these into one “fact”.

## Sensitive categories
Corruption, sexual violence, hate incidents, minors, personal safety, medical information and identifiable private individuals require stronger moderation/privacy controls. Sensitive submissions must not become public merely because they were submitted.

## Privacy
Collect only what is needed. Do not expose private reporter identity/contact details, IP addresses, moderation notes, private evidence or session/auth tokens.

For sensitive cases, keep exact location private and use a coarse public location when appropriate.

## Evidence
Validate file type/size server-side, sanitize media where appropriate, control metadata before publication, keep private evidence separate, and authorize every read path.

## Moderation
Support approve, reject, request changes, restrict visibility, redact sensitive information, link duplicates, and record reasons. Decisions should be auditable.

## Abuse prevention
Use appropriate rate limits, bot protection and abuse detection without collecting unnecessary personal information.

## Product boundaries
Kranti documents citizen reports and helps users access legitimate civic processes. It does not independently determine guilt and is not an emergency-response service.

## External communication
No automated accusation or complaint is sent without explicit user confirmation.

## Incidents
For security/privacy incidents: contain, preserve relevant logs, review access, remediate, and document lessons. Never put sensitive incident details in public logs/GitHub issues.
